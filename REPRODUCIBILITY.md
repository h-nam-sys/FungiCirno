# Reproducing Oyster Mushroom Cluster Monitoring

The workflow uses two complementary notebooks. Run the inference notebook first, then use its prediction-evidence bundle as input to the tracking notebook.

## Required resources

1. **Model artifacts:** [Oyster Mushroom Cluster Monitoring Models — Kaggle](https://www.kaggle.com/datasets/hnamedu/fungicirno-models), containing the selected checkpoints and canonical split manifest. The existing Kaggle URL is retained.
2. **Source images and annotations:** [Oyster mushroom clusters growth monitoring timelapses — Zenodo](https://doi.org/10.5281/zenodo.15041243), obtained separately. The dataset is not redistributed in this repository or in the model-artifact dataset.
3. **Inference notebook:** [`notebooks/full-inference.ipynb`](notebooks/full-inference.ipynb).
4. **Tracking notebook:** [`notebooks/tracking-and-growth-history.ipynb`](notebooks/tracking-and-growth-history.ipynb).
5. **Execution environment:** a Kaggle notebook session with a GPU accelerator. The full-resolution inference run is configured for CUDA.

## 1. Fresh inference and segmentation evaluation

1. Create a Kaggle notebook and import `notebooks/full-inference.ipynb`.
2. Attach the model-artifact dataset.
3. Obtain the original four-sequence source dataset from Zenodo and attach the sequence archives or extracted source directories, together with the tracked COCO annotation files.
4. Run the notebook from top to bottom. Its loader searches the Kaggle input and working directories and verifies the checkpoint and canonical manifest hashes. If automatic discovery is ambiguous, set `YOLO_CHECKPOINT_PATH`, `MASKRCNN_MODEL_ROOT`, `SPLIT_MANIFEST_PATH`, and/or `SOURCE_DATA_ROOT` explicitly in the configuration cell.
5. The notebook performs fresh inference on the 433 validation and 528 test frames (961 frames per model) and exports prediction records, segmentation and matched-instance geometry results, figures, provenance, and integrity checks. It may validate already completed fresh-inference records when resuming post-inference analysis after an interruption; the run manifest records that distinction.
6. Download the evidence bundle printed by the notebook's final cells. New output paths use the current project name; some imported historical evidence archives retain earlier filenames for compatibility.

The inference notebook also preserves the earlier tracker-comparison diagnostics in the evidence archive. These are historical development outputs. The paper's final tracking and growth-history metrics come from the separate frozen-tracker evaluation below.

## 2. Final tracking and growth-history evaluation

1. Import `notebooks/tracking-and-growth-history.ipynb` into a Kaggle notebook.
2. Attach the inference evidence bundle generated by `full-inference.ipynb` as a Kaggle input.
3. If more than one evidence bundle is found, set `EVIDENCE_BUNDLE_PATH` in the configuration cell to the intended archive or extracted directory.
4. Run the notebook from top to bottom. It verifies and loads the cached YOLO prediction records and source `GT_TRACK_ID` annotations, verifies the frozen tracker configuration hash, then evaluates the 528 sampled test frames from sequences 1 and 3.
5. Download the tracking-evaluation archive and figure archive produced in `/kaggle/working`.

This stage does not rerun YOLO26-L-seg or Mask R-CNN inference and does not tune tracker parameters on the test set. It applies the validation-selected frozen tracker configuration. The test sequences were inspected during exploratory tracker development, so these tracking results are retrospective, not an untouched independent test estimate.

## Dataset split and sampling

The source dataset contains 6,382 images. The canonical manifest selects 2,689 frames: 1,728 training, 433 validation, and 528 test frames. The test set consists of 261 frames from sequence 1 and 267 from sequence 3, sampled every eighth source frame. The source capture cadence is 15 minutes, so the nominal evaluation interval is two hours. Raw timestamps were unavailable for the evaluated frames; plotted elapsed time is nominal.

See [`DATASET.md`](DATASET.md) for source access and licence handling, and [`evidence/README.md`](evidence/README.md) for the evidence index.

## Recorded environment

The archived inference environment records Python 3.13.16, PyTorch 2.11.0+cu130, TorchVision 0.26.0+cu130, CUDA 13.0, Ultralytics 8.4.214, NumPy 2.1.3, pandas 2.3.3, and OpenCV 4.14.0 on an NVIDIA Tesla T4. The notebooks retain the Kaggle-provided PyTorch/TorchVision/CUDA stack rather than replacing it with an arbitrary GPU build.

## Interpretation and limitations

- Fresh recomputation establishes computational reproducibility, not an untouched test set; the test sequences were inspected during development.
- The custom frame-matching MOTA is project-specific and should not be described as a standard TrackEval/CLEAR-MOTA result.
- Measurements are image-space quantities unless a separate calibration is validated.
- The YOLO26-L-seg model predicts one cluster class and does not infer source maturity labels.
- See the paper and evidence archive for identity fragmentation, mixed-identity failures, and the strict 90% whole-track purity rule used for source-consistent growth histories.
